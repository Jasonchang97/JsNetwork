## 简介

JsNetwork 是一款跨平台的 HTTP/HTTPS 网络抓包分析工具，类似于 Charles Proxy、Fiddler 和 mitmproxy。它可以帮助开发者：

- 调试 Web 应用和 API 接口
- 分析网络请求和响应
- Mock 接口响应进行前端开发
- 检测和修复网络问题

## 安装与启动

### Windows 安装

**方法一：安装包**
1. 下载 `JsNetwork-v0.1.0-win32-setup.exe`
2. 双击运行安装程序
3. 按照向导提示完成安装
4. 从开始菜单或桌面快捷方式启动

**方法二：便携版**
1. 下载 `JsNetwork-v0.1.0-win32.zip`
2. 解压到任意目录
3. 双击 `JsNetwork.exe` 启动

### macOS 安装

1. 下载 `JsNetwork-v0.1.0-macOS.dmg`
2. 打开 DMG 文件
3. 将 JsNetwork.app 拖入 Applications 文件夹
4. 首次运行时，系统可能提示安全警告
   - 打开"系统偏好设置" → "安全性与隐私"
   - 点击"仍要打开"按钮

### 工具栏

| 按钮 | 功能 |
|------|------|
| 清空 | 清除所有捕获的请求 |
| HTTPS 解密 | 开启/关闭 MITM 解密功能 |
| 导出 HAR | 将请求导出为 HAR 格式文件 |
| 主题 | 切换深色/浅色主题 |
| 语言 | 切换中文/英文界面 |

### 流量列表

流量列表显示所有捕获的网络请求，包含以下信息：

- **ID**：请求序号
- **时间**：请求发起时间
- **方法**：HTTP 方法（GET/POST/PUT/DELETE 等）
- **主机**：目标服务器域名
- **路径**：请求路径
- **状态**：HTTP 状态码（带颜色标识）
  - 绿色：2xx 成功
  - 蓝色：3xx 重定向
  - 橙色：4xx 客户端错误
  - 红色：5xx 服务器错误
- **大小**：响应体大小
- **耗时**：请求总耗时

### 过滤与搜索

在流量列表上方的搜索框中输入关键字，可以过滤显示的请求：

- 输入域名：过滤特定网站的请求
- 输入路径：过滤特定接口
- 输入方法：如 `POST` 只显示 POST 请求
- 输入状态码：如 `404` 只显示 404 响应

## 基本使用

### 步骤 1：启动 JsNetwork

启动后，JsNetwork 会自动在 `localhost:9527` 启动代理服务器。

### 步骤 2：配置系统代理

#### Windows 系统代理设置

1. 打开"设置" → "网络和 Internet" → "代理"
2. 在"手动设置代理"部分：
   - 打开"使用代理服务器"
   - 地址填写：`127.0.0.1`
   - 端口填写：`9527`
3. 点击"保存"

#### macOS 系统代理设置

1. 打开"系统偏好设置" → "网络"
2. 选择当前使用的网络连接（如 Wi-Fi）
3. 点击"高级" → "代理"
4. 勾选"Web 代理 (HTTP)"和"安全 Web 代理 (HTTPS)"
5. 服务器填写：`127.0.0.1`，端口填写：`9527`
6. 点击"好" → "应用"

#### 浏览器代理设置（推荐使用扩展）

推荐使用浏览器代理扩展，可以快速切换代理：

- **Chrome**: SwitchyOmega、Proxy SwitchySharp
- **Firefox**: FoxyProxy、Proxy Switcher

### 步骤 3：开始抓包

配置好代理后，在浏览器中访问任意网站，JsNetwork 会自动捕获所有 HTTP 请求。

## HTTPS 抓包配置

默认情况下，JsNetwork 只能捕获 HTTP 明文请求。要捕获 HTTPS 请求，需要启用 MITM 解密功能。

### 启用 MITM

1. 点击工具栏的 "HTTPS 解密" 按钮
2. 首次启用时，程序会自动生成 CA 证书并尝试安装到系统信任库
3. 安装成功后，按钮变为启用状态

### 手动安装 CA 证书

如果自动安装失败，需要手动安装证书：

#### Windows 手动安装

1. 找到 CA 证书文件：
   ```
   C:\Users\<用户名>\AppData\Local\JsNetwork\certificates\ca.pem
   ```
2. 双击 `ca.pem` 文件
3. 点击"安装证书"
4. 选择"本地计算机" → "下一步"
5. 选择"将所有证书放入下列存储"
6. 点击"浏览" → 选择"受信任的根证书颁发机构"
7. 点击"确定" → "下一步" → "完成"

#### macOS 手动安装

1. 找到 CA 证书文件：
   ```
   ~/Library/Application Support/JsNetwork/certificates/ca.pem
   ```
2. 双击 `ca.pem` 文件，打开钥匙串访问
3. 在钥匙串列表中找到 "JsNetwork CA"
4. 双击证书 → 展开"信任" → 设置为"始终信任"
5. 输入系统密码确认

#### 浏览器证书安装

某些浏览器（如 Firefox）使用独立的证书存储，需要单独安装：

1. 打开 Firefox 设置 → 隐私与安全 → 证书 → 查看证书
2. 在"证书颁发机构"标签页点击"导入"
3. 选择 `ca.pem` 文件
4. 勾选"信任由此 CA 标识的网站" → 确定

### 验证证书安装

安装证书后，访问 `https://httpbin.org/get`，如果能正常显示请求内容且没有证书警告，说明证书安装成功。

## Mock 规则使用

Mock 功能可以拦截指定的请求并返回自定义响应，常用于：
- 前端开发时模拟后端接口
- 测试异常情况（如网络错误、超时）
- 离线开发

### 创建 Mock 规则

1. 点击左侧边栏的 "Mock" 标签
2. 点击 "+ 添加规则" 按钮
3. 配置规则：
   - **名称**：规则描述
   - **匹配模式**：选择匹配方式
   - **匹配内容**：输入匹配字符串
   - **动作**：选择响应方式

### 匹配模式

| 模式 | 说明 | 示例 |
|------|------|------|
| 精确匹配 | URL 完全相同 | `https://api.example.com/users` |
| 包含匹配 | URL 包含指定字符串 | `/api/users` |
| 通配符匹配 | 使用 `*` 匹配任意字符 | `https://api.example.com/*` |
| 正则匹配 | 使用正则表达式 | `https://api\.example\.com/users/\d+` |

### 响应动作

#### 本地映射 (Map Local)

将请求映射到本地文件：

1. 选择 "本地映射" 动作
2. 点击"浏览"选择本地文件
3. 设置响应的 Content-Type（可选）

支持的文件类型：
- JSON 文件 (`.json`)
- HTML 文件 (`.html`)
- XML 文件 (`.xml`)
- 纯文本文件 (`.txt`)
- 图片文件 (`.png`, `.jpg`, `.gif`)

#### 自动响应 (Auto Responder)

自定义响应内容：

1. 选择 "自动响应" 动作
2. 设置：
   - **状态码**：HTTP 状态码（如 200, 404, 500）
   - **响应头**：每行一个，格式为 `Key: Value`
   - **响应体**：响应内容

示例：模拟登录成功
```
状态码: 200
响应头:
Content-Type: application/json
响应体:
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "abc123"
  }
}
```

### 规则管理

- **启用/禁用**：点击规则左侧的开关
- **编辑**：双击规则或选中后点击"编辑"
- **删除**：选中规则后点击"- 删除"
- **排序**：拖动规则调整优先级（从上到下匹配）

## 断点调试

断点功能可以在请求发送前或响应返回前暂停，允许修改请求/响应内容。

### 设置断点

1. 点击左侧边栏的 "断点" 标签
2. 点击"添加断点"
3. 配置：
   - **匹配规则**：URL 匹配模式
   - **断点位置**：请求前 / 响应后
   - **条件**：可选，如只对 POST 请求断点

### 使用断点

当匹配的请求发生时：

1. 请求会暂停，状态栏显示 "断点命中"
2. 在详情面板中可以修改：
   - 请求头
   - 请求体
   - URL
   - 方法
3. 修改完成后点击"放行"发送请求
4. 响应返回后可能再次暂停（如果设置了响应断点）
5. 修改响应内容后点击"放行"返回给客户端

### 断点操作

| 操作 | 说明 |
|------|------|
| 放行 | 发送修改后的请求/响应 |
| 丢弃 | 阻止请求/响应，返回错误给客户端 |
| 跳过 | 不修改，直接放行 |

## Composer 使用

Composer 可以手动构造 HTTP 请求并发送，用于：
- 测试 API 接口
- 重放历史请求
- 修改请求参数重新发送

### 使用步骤

1. 点击左侧边栏的 "Composer" 标签
2. 填写请求信息：
   - **方法**：选择 GET/POST/PUT/DELETE 等
   - **URL**：输入完整的请求地址
   - **请求头**：每行一个，格式为 `Key: Value`
   - **请求体**：POST/PUT 请求的 Body 内容
3. 点击"发送"按钮
4. 下方显示响应结果

### 从已有请求创建

在流量列表中右键点击某个请求，选择"在 Composer 中打开"，可以快速基于已有请求创建新请求。

### 保存请求

可以将常用的请求保存为模板：
1. 点击"保存"按钮
2. 输入模板名称
3. 下次使用时从下拉列表选择模板

## 数据导出

### 导出 HAR 文件

HAR (HTTP Archive) 是一种标准的网络请求日志格式，可以被 Chrome DevTools、Firefox 等工具导入分析。

1. 点击工具栏的"导出 HAR"按钮
2. 选择保存位置
3. 输入文件名
4. 点击"保存"

导出的 HAR 文件包含：
- 所有请求/响应的完整信息
- 请求头和响应头
- 请求体和响应体
- 时间线数据（DNS、连接、TLS、TTFB 等）

### 在 Chrome 中查看 HAR

1. 打开 Chrome DevTools (F12)
2. 切换到 "Network" 标签
3. 点击 "Import HAR file" 按钮
4. 选择导出的 HAR 文件

### 复制请求信息

在流量列表中右键点击请求，可以：
- 复制 URL
- 复制 cURL 命令
- 复制请求头
- 复制响应头

## 常见问题

### Q: 为什么无法捕获 HTTPS 请求？

A: 需要启用 MITM 解密功能并安装 CA 证书：
1. 点击工具栏的 "HTTPS 解密" 按钮
2. 确保 CA 证书已正确安装到系统信任库
3. 如果使用 Firefox，需要单独安装证书到 Firefox 证书库

### Q: 为什么某些网站无法正常访问？

A: 可能的原因：
1. **证书未安装**：安装 CA 证书后重试
2. **证书固定 (Certificate Pinning)**：某些应用使用了证书固定，无法通过 MITM 解密
3. **双向 TLS (mTLS)**：需要客户端证书的网站无法解密
4. **代理设置错误**：检查代理配置是否正确

### Q: 如何只抓取特定网站的请求？

A: 使用流量列表上方的过滤功能：
1. 输入域名关键字（如 `api.example.com`）
2. 按 Enter 确认过滤
3. 只显示匹配的请求

### Q: 如何修改代理端口？

A: 当前版本默认使用 9527 端口，暂不支持在界面中修改。如需修改，需要重新编译程序。

### Q: 请求列表太多，如何清理？

A: 有以下方式：
1. 点击工具栏的"清空"按钮清除所有请求
2. 右键点击单个请求选择"删除"
3. 使用过滤功能只显示关注的请求

### Q: 如何导出特定请求？

A: 在流量列表中选中一个或多个请求（按住 Ctrl 多选），然后：
1. 右键点击选择"导出选中请求"
2. 或点击"导出 HAR"只导出选中的请求

### Q: Mock 规则不生效？

A: 检查以下几点：
1. 规则是否已启用（左侧开关）
2. 匹配模式和内容是否正确
3. 规则优先级（从上到下匹配，高优先级规则先生效）
4. 请求是否被代理捕获（检查代理设置）

### Q: 断点暂停后如何恢复？

A: 当请求被断点暂停时：
1. 在详情面板中查看/修改请求内容
2. 点击"放行"按钮继续发送
3. 或点击"丢弃"按钮阻止请求

### Q: 如何查看 WebSocket 消息？

A: WebSocket 连接会在流量列表中显示为 `WS` 协议：
1. 点击 WebSocket 连接查看详情
2. 在"消息"标签页查看所有 WebSocket 帧
3. 支持 Text、Binary、Ping、Pong、Close 帧类型

### Q: 程序占用内存过多？

A: 长时间运行可能积累大量请求数据：
1. 定期点击"清空"释放内存
2. 使用过滤减少显示的请求数量
3. 关闭不需要的 MITM 解密功能
