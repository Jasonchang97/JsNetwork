## 1. 产品简介

JsNetwork 是一款跨平台（macOS / Windows）的 HTTP/HTTPS 网络抓包分析工具，类似 Charles Proxy / Fiddler，但免费开源。

**核心能力：**
- 捕获并解密 HTTP/HTTPS 网络请求
- 以可视化方式展示请求/响应的完整内容
- 支持 Mock 模拟、断点调试、请求构造等高级功能
- 支持导出标准 HAR 格式文件

**谁需要它：**

| 角色 | 典型场景 |
|------|---------|
| 开发工程师 | 调试 API 接口、排查网络异常、验证请求参数 |
| 测试工程师 | 验证接口返回、模拟异常场景、回归测试 |
| 产品经理 | 查看 App 实际请求了哪些数据、验证功能逻辑 |
| 运营人员 | 排查页面加载问题、确认埋点上报、导出数据给技术团队 |

## 2. 安装与启动

### macOS 安装

1. 双击 `JsNetwork-0.1.0-macOS.dmg`
2. 将 `JsNetwork.app` 拖入 `Applications` 文件夹
3. 首次启动时，系统会弹出证书信任提示，输入密码授权（用于 HTTPS 解密）

### Windows 安装

1. 运行 `JsNetwork-0.1.0-Setup.exe`
2. 按向导完成安装
3. 首次启动时，如需 HTTPS 解密，按提示安装根证书

### 启动后

- 程序自动在 `localhost:9527` 启动代理服务
- 状态栏显示 "代理: localhost:9527 ●" 表示代理已就绪
- 界面默认为中文，可通过工具栏切换为 English

## 4. 快速上手

### 第一步：配置代理

将系统或浏览器的 HTTP/HTTPS 代理设置为：

```
地址：127.0.0.1
端口：9527
```

**macOS 设置方法：**
- 系统偏好设置 → 网络 → 高级 → 代理 → Web 代理 / 安全 Web 代理 → `127.0.0.1:9527`

**浏览器插件推荐：**
- Chrome: SwitchyOmega / Proxy SwitchySharp
- Firefox: FoxyProxy

### 第二步：开启 HTTPS 解密

点击工具栏 **"HTTPS 解密"** 按钮（默认关闭）。

开启后，程序会拦截 HTTPS 流量并解密为明文。首次使用需要安装根证书（程序会自动提示）。

### 第三步：开始使用

打开浏览器访问任意网页，JsNetwork 会实时显示所有网络请求。

## 5. 功能详解

### 5.1 流量抓取

流量列表以表格形式实时展示所有经过代理的网络请求。

**列说明：**

| 列名 | 说明 |
|------|------|
| # | 请求序号（自动递增） |
| 方法 | HTTP 方法（GET / POST / PUT / DELETE 等） |
| 主机 | 目标服务器域名 |
| 路径 | 请求路径 |
| 状态 | HTTP 状态码，颜色区分：2xx 绿色、3xx 蓝色、4xx 橙色、5xx 红色 |
| 大小 | 响应体大小 |
| 耗时 | 从请求发出到响应完成的总耗时 |

**操作：**
- 点击任意行查看详情
- 双击列标题边缘可调整列宽
- 点击列标题可按该列排序
- 工具栏 **"清除"** 按钮清空所有已捕获的请求

### 5.2 HTTPS 解密

默认状态下，HTTPS 流量只能看到加密的 CONNECT 隧道。开启 HTTPS 解密后：

1. 程序自动为目标域名生成伪造证书
2. 与浏览器建立 TLS 连接（使用伪造证书）
3. 与真实服务器建立 TLS 连接
4. 双向解密转发，流量以明文展示

**证书管理：**
- 首次启动时自动生成 CA 根证书
- 尝试自动安装到系统信任库（需管理员权限）
- 如自动安装失败，可手动安装：
  ```bash
  # macOS
  sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain \
    ~/Library/Application\ Support/JsNetwork/certificates/ca.pem
  ```

### 5.3 请求/响应详情

选中一个请求后，下方详情面板展示 6 个 Tab：

**概览：**
- URL、方法、状态码、协议版本
- 主机、路径
- 请求/响应大小、耗时、时间戳

**请求头：**
- 所有 HTTP 请求头，键值对格式展示

**请求体：**
- 自动识别 Content-Type 并解析：
  - `application/json` → JSON 格式化 + 语法高亮
  - `application/x-www-form-urlencoded` → 表单键值对
  - `multipart/form-data` → 多部分表单（含文件上传）
  - `text/xml` → XML 缩进格式化
  - `image/*` → 图片预览
  - 其他 → 原文 / Hex dump

**响应头：**
- 所有 HTTP 响应头

**响应体：**
- 与请求体相同的自动解析能力
- 支持 gzip / deflate / chunked 自动解码

**时间线：**
- 瀑布图展示各阶段耗时：DNS → TCP 连接 → TLS 握手 → 首字节 → 下载

### 5.4 过滤与搜索

列表上方的搜索栏支持多种过滤方式：

| 输入内容 | 匹配规则 |
|---------|---------|
| `github` | 匹配主机或路径中包含 "github" 的请求 |
| `POST` | 匹配方法为 POST 的请求 |
| `api.example.com` | 精确匹配主机 |
| `/login` | 匹配路径中包含 "/login" 的请求 |
| `404` | 匹配状态码为 404 的请求 |

### 5.5 Mock 模拟

点击左侧栏 **"模拟"** 进入 Mock 管理面板。

**添加规则：**
1. 点击 **"+ 添加规则"**
2. 填写匹配条件和响应内容

**规则配置：**

| 字段 | 说明 |
|------|------|
| 启用 | 勾选启用/禁用该规则 |
| 匹配 | 匹配方式：精确 / 包含 / 通配符 / 正则 |
| 模式 | URL 匹配模式（如 `api.example.com` 或 `*/login`） |
| 动作 | MapLocal（映射本地文件）/ AutoResponder（自动响应） |
| 目标 | 本地文件路径 或 `[状态码] Content-Type` |

**使用场景：**
- 将某个 API 请求拦截，返回自定义 JSON 数据
- 模拟 500 错误，测试前端错误处理
- 将线上资源替换为本地开发版本

### 5.6 请求构造器

点击左侧栏 **"构造器"** 进入请求构造面板。

**使用方法：**
1. 选择 HTTP 方法（GET / POST / PUT / DELETE / PATCH / HEAD / OPTIONS）
2. 输入完整的请求 URL
3. （可选）填写自定义请求头
4. （可选）填写请求体
5. 点击 **"发送"**

**响应区域会展示：**
- HTTP 状态码和状态描述
- 响应头
- 响应体

**典型用途：**
- 从流量列表复制一个请求，修改参数后重放
- 测试新增的 API 接口
- 构造特殊请求头测试服务端行为

### 5.7 数据导出

工具栏 **"导出 HAR"** 按钮将当前所有捕获的请求导出为 HAR 1.2 格式文件。

HAR 文件可以：
- 导入到 Chrome DevTools (Network → Import HAR)
- 导入到 Charles Proxy
- 作为 bug 报告附件，附带完整网络现场
- 用 HAR 分析工具进行性能分析

## 6. 场景指南

### 6.1 开发工程师

**场景：调试 API 接口**

1. 开启 HTTPS 解密
2. 配置浏览器代理，访问目标页面
3. 在流量列表中找到目标 API 请求
4. 查看请求头中的 Authorization、Content-Type 是否正确
5. 查看请求体中的参数是否符合预期
6. 查看响应体中的返回数据
7. 如有问题，用构造器修改参数后重放验证

**场景：排查跨域问题**

1. 查看响应头中的 `Access-Control-Allow-Origin`、`Access-Control-Allow-Methods`
2. 确认预检请求（OPTIONS）是否正常返回
3. 对比本地和线上环境的请求差异

**场景：性能优化**

1. 查看时间线 Tab，定位耗时最长的阶段
2. DNS 慢 → 考虑 DNS 预解析
3. TLS 慢 → 考虑连接复用
4. TTFB 慢 → 排查服务端处理时间
5. 下载慢 → 考虑响应压缩、分页加载

---

### 6.2 测试工程师

**场景：接口回归测试**

1. 开启抓包，执行测试用例
2. 逐一检查关键接口的请求参数和返回状态
3. 对比历史 HAR 文件，确认接口行为未变化

**场景：模拟异常测试**

1. 进入 **"模拟"** 面板
2. 添加规则：匹配 `api.example.com/login`
3. 设置动作为 AutoResponder，状态码 500，响应体 `{"error": "Internal Server Error"}`
4. 触发登录操作，验证前端是否正确处理 500 错误
5. 测试完成后禁用或删除规则

**场景：弱网模拟**

1. 添加 Mock 规则，匹配特定资源
2. 使用 MapLocal 动作，指向一个较大的本地文件
3. 观察页面在大资源加载下的表现

**场景：边界值测试**

1. 使用构造器发送超长 URL、特殊字符请求头、超大请求体
2. 验证服务端的参数校验和错误处理

---

### 6.3 产品经理

**场景：查看 App 网络行为**

1. 手机/模拟器配置代理指向 JsNetwork
2. 操作 App 的各个功能
3. 观察流量列表，了解 App 在后台请求了哪些接口
4. 确认是否有不必要的数据上报或隐私采集

**场景：验证新功能上线**

1. 开启抓包，使用新功能
2. 确认对应的 API 请求已发出
3. 查看响应数据，确认功能逻辑正确
4. 如有问题，截图 HAR 文件反馈给开发

**场景：竞品分析**

1. 抓取竞品 App 的网络请求
2. 分析其接口设计、数据结构
3. 了解其加载策略（预加载、懒加载、缓存策略）

---

### 6.4 运营人员

**场景：排查页面加载异常**

1. 配置代理，访问目标页面
2. 查看是否有请求返回 4xx / 5xx 错误
3. 确认静态资源（JS/CSS/图片）是否正常加载
4. 将异常请求的 HAR 文件导出，提交给技术团队

**场景：确认埋点上报**

1. 开启抓包，执行用户操作
2. 搜索埋点相关的域名或路径
3. 检查上报的参数是否完整、事件名是否正确
4. 确认上报频率和时机是否符合预期

**场景：数据导出给技术团队**

1. 复现问题操作
2. 点击 **"导出 HAR"**
3. 将 HAR 文件通过工单/邮件发送给开发
4. HAR 文件包含完整的请求/响应现场，开发可直接导入分析

## 7. 常见问题

### Q: 开启 HTTPS 解密后，部分网站打不开？

**原因：** 该网站启用了 Certificate Pinning（证书固定），不允许使用非原始证书。

**解决：** 关闭 HTTPS 解密，或在浏览器中跳过该网站的证书验证。部分 App（如银行类）强制 Pinning，无法解密。

### Q: macOS 提示"无法验证开发者"？

**解决：**
- 系统偏好设置 → 安全性与隐私 → 通用 → 点击 "仍要打开"
- 或右键点击 JsNetwork.app → 打开

### Q: 代理设置后无法上网？

**原因：** JsNetwork 未运行，或代理端口不匹配。

**解决：**
1. 确认 JsNetwork 正在运行，状态栏显示 "代理: localhost:9527 ●"
2. 确认系统代理地址为 `127.0.0.1`，端口为 `9527`
3. 如果 JsNetwork 已关闭，请手动取消系统代理设置

### Q: 请求体显示为空？

**可能原因：**
- 请求使用了 `chunked` 分块传输但数据尚未完全接收
- 请求使用了 `gzip` 压缩但解压失败
- 请求体确实为空（如 GET 请求）

**解决：** 确认请求的 Content-Type 和 Transfer-Encoding 头信息。

### Q: 如何抓取手机端的请求？

1. 确保手机和电脑在同一局域网
2. 查看电脑的局域网 IP（如 `192.168.1.100`）
3. 手机 Wi-Fi 设置中配置 HTTP 代理为手动，填写 `192.168.1.100:9527`
4. 手机浏览器访问 `http://192.168.1.100:9527` 下载并安装 CA 证书
5. iOS: 设置 → 通用 → 关于本机 → 证书信任设置 → 启用
6. Android: 设置 → 安全 → 加密与凭据 → 安装证书

### Q: 如何只抓取特定域名的请求？

在搜索栏输入域名关键字即可过滤。例如输入 `api.github.com` 只显示 GitHub API 请求。

### Q: 导出的 HAR 文件如何分析？

- **Chrome DevTools:** F12 → Network → 右上角齿轮 → Import HAR
- **在线工具:** [Google HAR Analyzer](https://toolbox.googleapps.com/apps/har_analyzer/)
- **Charles Proxy:** File → Import → HAR

## 附录：Body 支持的 Content-Type 类型

| Content-Type | 解析方式 |
|---|---|
| `application/json` | JSON 格式化 + 语法高亮（键名蓝色、字符串橙色、数字绿色） |
| `application/x-www-form-urlencoded` | 解析为 key = value 表单对 |
| `multipart/form-data` | 解析各 Part 的 name、filename、Content-Type 和 body |
| `text/xml` / `application/xml` | XML 缩进格式化 |
| `text/html` | 原文展示 |
| `image/png` / `jpeg` / `gif` / `webp` / `svg` | 图片预览 |
| 二进制数据 | 大小信息 + Hex dump 预览 |
| 其他文本 | 自动尝试 JSON 解析，失败则原文展示 |
| 所有类型 | Hex 视图：地址 + 十六进制 + ASCII 可视化 |
